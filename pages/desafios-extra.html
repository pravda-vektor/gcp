Desafíos Extra

Cinco ejercicios para practicar con el mismo agente, el mismo proyecto y las tablas que ya existen. No necesitas crear documentos ni datasets nuevos.

Mismo entorno, más profundidad

Los desafíos 1–3 reutilizan criterio_revision.txt. Los desafíos 4–5 usan criterios definidos directamente en el prompt para poder trabajar con instrumentos y valorizaciones_instrumentos.

Los prompts y el SQL están incluidos

Puedes ejecutar directamente el prompt del desafío. El SQL de referencia está disponible debajo de cada ejercicio y viene explicado. Si quieres mayor dificultad, intenta primero y luego compara.

SELECT
  m.movimiento_id,
  m.cuenta_id,
  m.fecha_movimiento,
  m.hora,
  m.tipo_movimiento,
  m.canal,
  m.monto,
  m.moneda,
  m.es_internacional,
  m.categoria_contraparte,
  c.cliente_id,
  c.producto,
  c.estado,
  cl.segmento,
  cl.region,
  cl.nivel_riesgo,
  cl.canal_preferente
FROM `arched-osprey-506820-i9.analitica_bancaria_demo.movimientos_diarios` AS m
JOIN `arched-osprey-506820-i9.analitica_bancaria_demo.cuentas_productos` AS c
  ON m.cuenta_id = c.cuenta_id
JOIN `arched-osprey-506820-i9.analitica_bancaria_demo.clientes` AS cl
  ON c.cliente_id = cl.cliente_id
WHERE m.canal IN ('APP', 'WEB')
  AND m.es_internacional = 1
  AND m.monto > 2000000
  AND c.producto = 'Tarjeta de Crédito'
ORDER BY m.fecha_movimiento, m.hora, m.movimiento_id;

Qué enseña esta consulta

  • El criterio sigue aplicándose en movimientos_diarios + cuentas_productos.
  • El segundo JOIN no decide qué operaciones cumplen: solo las enriquece con atributos del cliente.
  • Como clientes tiene un registro por cliente, el grano esperado sigue siendo una fila por movimiento seleccionado.

Trabaja con el alumno-XX. Reemplaza XX por mi número de alumno.

Objetivo:

gs://banco-curso-vertex-datos/alumnos/prueba-tipo/alumnos/alumno-XX/insumos/criterio_revision.txt

WITH clientes_objetivo AS (
  SELECT DISTINCT
    c.cliente_id
  FROM `arched-osprey-506820-i9.analitica_bancaria_demo.movimientos_diarios` AS m
  JOIN `arched-osprey-506820-i9.analitica_bancaria_demo.cuentas_productos` AS c
    ON m.cuenta_id = c.cuenta_id
  WHERE m.canal IN ('APP', 'WEB')
    AND m.es_internacional = 1
    AND m.monto > 2000000
    AND c.producto = 'Tarjeta de Crédito'
),
ultima_fecha AS (
  SELECT
    e.cliente_id,
    MAX(e.fecha_corte) AS fecha_corte
  FROM `arched-osprey-506820-i9.analitica_bancaria_demo.exposicion_crediticia` AS e
  JOIN clientes_objetivo AS o
    ON e.cliente_id = o.cliente_id
  GROUP BY e.cliente_id
),
resumen_exposicion AS (
  SELECT
    e.cliente_id,
    e.fecha_corte,
    SUM(e.exposicion) AS exposicion_total,
    SUM(e.limite) AS limite_total,
    SUM(e.garantia) AS garantia_total,
    MAX(e.dias_mora) AS max_dias_mora,
    COUNT(*) AS productos_crediticios
  FROM `arched-osprey-506820-i9.analitica_bancaria_demo.exposicion_crediticia` AS e
  JOIN ultima_fecha AS u
    ON e.cliente_id = u.cliente_id
   AND e.fecha_corte = u.fecha_corte
  GROUP BY e.cliente_id, e.fecha_corte
)
SELECT
  r.cliente_id,
  r.fecha_corte,
  cl.segmento,
  cl.region,
  cl.nivel_riesgo,
  cl.canal_preferente,
  r.exposicion_total,
  r.limite_total,
  r.garantia_total,
  r.max_dias_mora,
  r.productos_crediticios
FROM resumen_exposicion AS r
JOIN `arched-osprey-506820-i9.analitica_bancaria_demo.clientes` AS cl
  ON r.cliente_id = cl.cliente_id
ORDER BY r.exposicion_total DESC, r.cliente_id;

Qué enseña esta consulta

  • DISTINCT cliente_id evita que un cliente con varias operaciones se replique antes de consultar exposición.
  • MAX(fecha_corte) define la fotografía más reciente de cada cliente.
  • Las exposiciones se agregan antes de volver a incorporar atributos del cliente, evitando multiplicaciones de filas.

WITH clientes_objetivo AS (
  SELECT DISTINCT
    c.cliente_id
  FROM `arched-osprey-506820-i9.analitica_bancaria_demo.movimientos_diarios` AS m
  JOIN `arched-osprey-506820-i9.analitica_bancaria_demo.cuentas_productos` AS c
    ON m.cuenta_id = c.cuenta_id
  WHERE m.canal IN ('APP', 'WEB')
    AND m.es_internacional = 1
    AND m.monto > 2000000
    AND c.producto = 'Tarjeta de Crédito'
),
ultima_fecha AS (
  SELECT
    e.cliente_id,
    MAX(e.fecha_corte) AS fecha_corte
  FROM `arched-osprey-506820-i9.analitica_bancaria_demo.exposicion_crediticia` AS e
  JOIN clientes_objetivo AS o
    ON e.cliente_id = o.cliente_id
  GROUP BY e.cliente_id
),
exposicion_cliente AS (
  SELECT
    e.cliente_id,
    SUM(e.exposicion) AS exposicion_total,
    SUM(e.limite) AS limite_total,
    SUM(e.garantia) AS garantia_total,
    MAX(e.dias_mora) AS max_dias_mora
  FROM `arched-osprey-506820-i9.analitica_bancaria_demo.exposicion_crediticia` AS e
  JOIN ultima_fecha AS u
    ON e.cliente_id = u.cliente_id
   AND e.fecha_corte = u.fecha_corte
  GROUP BY e.cliente_id
)
SELECT
  cl.segmento,
  cl.nivel_riesgo,
  COUNT(*) AS clientes,
  SUM(ec.exposicion_total) AS exposicion_total,
  SUM(ec.limite_total) AS limite_total,
  SUM(ec.garantia_total) AS garantia_total,
  MAX(ec.max_dias_mora) AS max_dias_mora
FROM exposicion_cliente AS ec
JOIN `arched-osprey-506820-i9.analitica_bancaria_demo.clientes` AS cl
  ON ec.cliente_id = cl.cliente_id
GROUP BY cl.segmento, cl.nivel_riesgo
ORDER BY exposicion_total DESC, cl.segmento, cl.nivel_riesgo;

Qué enseña esta consulta

  • Primero se obtiene un único resumen por cliente; recién después se hace el GROUP BY.
  • Esto evita contar varias veces la misma exposición por haber partido de movimientos individuales.
  • El grano final pasa a ser una fila por combinación segmento + nivel_riesgo.

- Para cada instrumento utiliza solo su fecha_valorizacion más reciente.

WITH valorizaciones_ordenadas AS (
  SELECT
    v.*,
    ROW_NUMBER() OVER (
      PARTITION BY v.instrumento_id
      ORDER BY v.fecha_valorizacion DESC
    ) AS rn
  FROM `arched-osprey-506820-i9.analitica_bancaria_demo.valorizaciones_instrumentos` AS v
)
SELECT
  i.instrumento_id,
  i.tipo_instrumento,
  i.tipo_emisor,
  i.moneda,
  i.fecha_vencimiento,
  i.tasa_cupon,
  i.nominal,
  v.fecha_valorizacion,
  v.precio_referencia,
  v.tasa_referencia,
  v.valor_mercado,
  v.pnl_diario
FROM valorizaciones_ordenadas AS v
JOIN `arched-osprey-506820-i9.analitica_bancaria_demo.instrumentos` AS i
  ON v.instrumento_id = i.instrumento_id
WHERE v.rn = 1
  AND v.pnl_diario < 0
ORDER BY v.pnl_diario ASC, i.instrumento_id;

Qué enseña esta consulta

  • ROW_NUMBER() permite elegir la valorización más reciente de cada instrumento.
  • El filtro pnl_diario < 0 se aplica después de fijar cuál es la observación vigente.
  • También muestra que el agente puede trabajar con un criterio entregado directamente por el usuario, no solo con un documento.

Úsalo como solución de referencia

Si quieres más dificultad, intenta primero con el prompt y compara después tu consulta con esta versión.

WITH valorizaciones_ordenadas AS (
  SELECT
    v.*,
    ROW_NUMBER() OVER (
      PARTITION BY v.instrumento_id
      ORDER BY v.fecha_valorizacion DESC
    ) AS rn
  FROM `arched-osprey-506820-i9.analitica_bancaria_demo.valorizaciones_instrumentos` AS v
)
SELECT
  i.tipo_instrumento,
  i.tipo_emisor,
  COUNT(*) AS instrumentos,
  SUM(i.nominal) AS nominal_total,
  SUM(v.valor_mercado) AS valor_mercado_total,
  SUM(v.pnl_diario) AS pnl_diario_total,
  AVG(v.tasa_referencia) AS tasa_referencia_promedio
FROM valorizaciones_ordenadas AS v
JOIN `arched-osprey-506820-i9.analitica_bancaria_demo.instrumentos` AS i
  ON v.instrumento_id = i.instrumento_id
WHERE v.rn = 1
GROUP BY i.tipo_instrumento, i.tipo_emisor
ORDER BY valor_mercado_total DESC, i.tipo_instrumento, i.tipo_emisor;

Qué enseña esta consulta

  • Primero controla el grano temporal: una valorización por instrumento.
  • Después relaciona atributos del instrumento y recién entonces agrega.
  • El resultado final ya no representa instrumentos individuales, sino grupos de tipo_instrumento + tipo_emisor.
