GoogleSQL — agregaciones

Las agregaciones permiten pasar de filas individuales a medidas resumidas: cuántos registros hay, cuánto suman, cuál es el promedio o cómo se comparan grupos.

1. De filas individuales a información resumida

Hasta ahora, una fila del resultado seguía representando normalmente un cliente, una cuenta o un movimiento. Cuando agregamos, varias filas pueden resumirse en un único resultado.

Muchas cuentas individuales
↓
GROUP BY producto
↓
Una fila resumida por producto
Idea clave Una agregación cambia el nivel de detalle del resultado. Antes de interpretar una cifra, pregunta siempre: ¿qué representa ahora una fila?

2. Funciones agregadas principales

GoogleSQL incluye funciones que resumen los valores de un grupo.

FunciónQué respondeEjemplo conceptual
COUNT(*)¿Cuántas filas hay?Cantidad de cuentas.
SUM(campo)¿Cuánto suman los valores?Saldo total.
AVG(campo)¿Cuál es el promedio?Saldo promedio.
MIN(campo)¿Cuál es el valor mínimo?Saldo mínimo.
MAX(campo)¿Cuál es el valor máximo?Saldo máximo.
 
SELECT
  COUNT(*) AS cantidad_cuentas,
  SUM(saldo_actual) AS saldo_total,
  AVG(saldo_actual) AS saldo_promedio,
  MIN(saldo_actual) AS saldo_minimo,
  MAX(saldo_actual) AS saldo_maximo
FROM `arched-osprey-506820-i9.analitica_bancaria_demo.cuentas_productos`;
Sin GROUP BY Esta consulta resume toda la tabla en una sola fila.

3. GROUP BY: resumir por categoría

GROUP BY crea grupos usando uno o más campos. Las funciones agregadas se calculan por separado para cada grupo.

SELECT
  producto,
  COUNT(*) AS cantidad_cuentas,
  SUM(saldo_actual) AS saldo_total,
  AVG(saldo_actual) AS saldo_promedio
FROM `arched-osprey-506820-i9.analitica_bancaria_demo.cuentas_productos`
GROUP BY producto
ORDER BY saldo_total DESC;

Lectura natural:

“Agrupa las cuentas por producto y, para cada producto, calcula cuántas cuentas hay, cuánto saldo suman y cuál es el saldo promedio.”

4. GROUP BY cambia el grano

Este punto es más importante que memorizar la sintaxis. En la tabla original cuentas_productos, una fila representa una cuenta/producto asociado a un cliente. Después de agrupar por producto, una fila representa un producto resumido.

Antes

1 fila = 1 cuenta/producto.

Después

1 fila = 1 valor distinto de producto.

Error frecuente No interpretes un resultado agregado como si todavía contuviera el detalle individual original. El resumen pierde detalle deliberadamente.

5. WHERE y HAVING no hacen lo mismo

Ambos filtran, pero actúan en momentos diferentes de la consulta.

CláusulaQué filtraMomento conceptual
WHEREFilas individuales.Antes de agrupar.
HAVINGGrupos ya agregados.Después de agrupar.
 
SELECT
  producto,
  COUNT(*) AS cantidad_cuentas,
  AVG(saldo_actual) AS saldo_promedio
FROM `arched-osprey-506820-i9.analitica_bancaria_demo.cuentas_productos`
WHERE estado = 'Activa'
GROUP BY producto
HAVING COUNT(*) >= 20
ORDER BY cantidad_cuentas DESC;

La lectura correcta es:

  1. Primero conserva solo las cuentas activas.
  2. Después las agrupa por producto.
  3. Calcula las métricas por grupo.
  4. Finalmente conserva solo los grupos con al menos 20 cuentas.

6. COUNT(DISTINCT ...): contar entidades únicas

COUNT(*) cuenta filas. Eso no siempre equivale a contar entidades únicas.

Si un cliente puede aparecer varias veces, podemos contar identificadores únicos:

SELECT
  COUNT(*) AS filas,
  COUNT(DISTINCT cliente_id) AS clientes_unicos
FROM `arched-osprey-506820-i9.analitica_bancaria_demo.exposicion_crediticia`;
Pregunta antes de contar ¿Quiero contar filas, cuentas, clientes, movimientos o algo distinto? Elegir la función correcta depende del grano.

7. COUNTIF: contar filas que cumplen una condición

COUNTIF cuenta cuántas filas evalúan una condición booleana como verdadera.

SELECT
  canal,
  COUNT(*) AS movimientos,
  COUNTIF(es_internacional = 1) AS movimientos_internacionales
FROM `arched-osprey-506820-i9.analitica_bancaria_demo.movimientos_diarios`
GROUP BY canal
ORDER BY movimientos DESC;
Ventaja Puedes calcular el total y un subconjunto condicionado dentro de la misma agrupación.

8. NULL y agregaciones

Los valores NULL requieren atención porque no todas las funciones los tratan igual.

ExpresiónComportamiento básico
COUNT(*)Cuenta todas las filas del grupo.
COUNT(columna)Cuenta las filas donde esa expresión no es NULL.
SUM / AVG / MIN / MAXNormalmente ignoran NULL al agregar.
No reemplaces NULL por cero automáticamente Cero y “valor ausente” no significan necesariamente lo mismo. Decide cómo tratar NULL según el significado del campo y la pregunta analítica.

9. ¿Dónde aparece esto en la Prueba Tipo?

La consulta principal de la evaluación no necesita resumir los cinco registros finales por grupo: debe conservar el detalle de cada operación que cumple el criterio. Por eso, las agregaciones no son el núcleo del SQL principal.

Pero siguen siendo útiles para verificar Una consulta separada de comprobación podría usar COUNT(*) para contar cuántas operaciones cumple el filtro. Esa verificación manual no reemplaza el resultado detallado que debe entregar el agente.

Esta distinción es importante: detalle para evidenciar cada caso y agregación para resumir o comprobar son necesidades distintas.
