Prueba Tipo

Recuperación y verificación

Esta etapa cubre qué hacer si Preview se interrumpe, cómo comprobar los tres archivos generados y cómo verificar de forma independiente que el SQL realmente selecciona las operaciones correctas.

Paso 07

Recuperar una ejecución interrumpida

Mismos rescates del paso 06 Los dos bloques que aparecen aquí son exactamente los mismos prompts mostrados debajo del prompt principal de ejecución. Este paso existe para explicar cuándo usar cada uno y cómo revisar los eventos antes de pegarlos.

Si el agente terminó todas las operaciones y entregó una respuesta final normal, no necesitas usar ningún prompt de recuperación. Continúa directamente al paso 08.

A veces Preview alcanza a leer archivos, consultar BigQuery o escribir resultados, pero se queda en las cajas de herramientas y no entrega una respuesta humana. Eso no significa que debas empezar de nuevo: primero revisa qué operaciones ya tienen resultado.

No vuelvas a ejecutar el prompt principal a ciegas Primero revisa qué tool calls ya finalizaron. El objetivo es conservar el trabajo correcto y completar únicamente lo que falte.

Diagnóstico rápido

SituaciónQué hacer
Las herramientas necesarias terminaron correctamente, pero no apareció la respuesta final.Usa el rescate “solo falta respuesta final”.
Algunas operaciones terminaron, pero todavía faltan escrituras u otros pasos.Usa el rescate “completar solo lo pendiente”.
Apareció 429 / Resource exhausted antes de cualquier tool call.Vuelve a intentar. Si se repite, refresca la página y ejecuta nuevamente. Si persiste, espera unos minutos y reintenta.
Apareció 429 / Resource exhausted después de uno o más tool calls.No empieces de cero. Revisa cuáles operaciones tienen tool result y recupera solamente lo que falte.
No sabes si un archivo fue escrito.Comprueba primero Cloud Storage antes de pedir otra escritura.
Si el error de recursos persiste Refresca la página y vuelve a intentar. Si sigue apareciendo, espera unos minutos antes de probar otra vez. Un error de capacidad puede ser temporal y no requiere cambiar el prompt.
Recuerda Un tool call seguido por su tool result es un ciclo normal. No lo cuentes como dos ejecuciones.

Cuando todas las operaciones terminaron y solo falta la respuesta

Usa exactamente este prompt si ya comprobaste que las lecturas, la consulta y las escrituras necesarias finalizaron correctamente.

🛟 PROMPT DE RECUPERACIÓN · solo respuesta final 
Las operaciones solicitadas anteriormente ya fueron ejecutadas.
No utilices ninguna herramienta nuevamente.
Utiliza exclusivamente los resultados ya obtenidos y entrega ahora la respuesta textual final pendiente de acuerdo con mi solicitud anterior.
No afirmes resultados o acciones que no estén respaldados por las ejecuciones ya realizadas.
Qué debe ocurrir El agente debe responder utilizando los resultados ya obtenidos, sin volver a leer Storage, revisar esquemas, ejecutar SQL ni escribir archivos.

Cuando todavía faltan operaciones

Usa este segundo prompt si algunas operaciones ya finalizaron, pero todavía quedan pasos pendientes —por ejemplo, una o más escrituras en Cloud Storage.

🛟 PROMPT DE RECUPERACIÓN · completar solo lo pendiente 
Continúa la tarea anterior exactamente desde el punto en que se interrumpió.
No repitas ninguna operación que ya haya finalizado correctamente.
Utiliza los resultados disponibles en esta conversación y completa únicamente las operaciones pendientes de mi solicitud anterior.
No vuelvas a leer una fuente, consultar un esquema ni ejecutar una consulta SQL si esa operación ya fue completada correctamente.
Debe existir como máximo una única ejecución analítica mediante execute_sql_readonly.
Completa las escrituras pendientes en Cloud Storage y, cuando hayan terminado, entrega la respuesta textual solicitada originalmente.
No afirmes que una operación fue completada si no existe evidencia de su ejecución exitosa.
Este rescate ya fue validado En el flujo de prueba permitió continuar después de lectura + esquemas + una única consulta y completar solamente las escrituras que faltaban.

Comprobación del paso 07

  • No repetiste execute_sql_readonly si ya había finalizado.
  • No volviste a leer criterio_revision.txt si ya estaba leído.
  • Solo se completaron las operaciones pendientes.
  • La ejecución terminó con una respuesta textual visible.
Paso 08

Revisar los archivos generados en Cloud Storage

No te limites a confiar en el mensaje del agente. Verifica directamente los objetos en tu carpeta.

Archivos esperados

ArchivoRuta esperadaQué revisar
consulta.sql alumno-XX/resultados/ JOIN por cuenta_id, cuatro condiciones, sin filtros extra.
resultado.csv alumno-XX/resultados/ 13 encabezados y 5 registros en los datos de práctica.
informe_final.md alumno-XX/informe/ Fuentes, criterio, resultados, interpretación, conclusión y limitaciones.

Procedimiento

  1. Abre Cloud Storage.
  2. Entra a tu carpeta alumno-XX/.
  3. Abre resultados/ y confirma que existen consulta.sql y resultado.csv.
  4. Abre informe/ y confirma que existe informe_final.md.
  5. Inspecciona el contenido de cada archivo.
Existir no basta Un archivo vacío, truncado o con contenido distinto de lo solicitado no constituye una entrega correcta.

Qué debería contener resultado.csv

Los encabezados deben corresponder a estas 13 columnas:

movimiento_id,cuenta_id,fecha_movimiento,hora,tipo_movimiento,canal,monto,moneda,es_internacional,categoria_contraparte,cliente_id,producto,estado
Paso 09

Verificar la consulta directamente en BigQuery

Objetivo

Comprobar que el SQL guardado realmente produce el resultado esperado cuando se ejecuta directamente en BigQuery.

Procedimiento

  1. Abre consulta.sql en Cloud Storage.
  2. Copia el SQL completo.
  3. Abre BigQuery Studio.
  4. Abre una pestaña nueva del editor SQL.
  5. Pega la consulta sin modificarla.
  6. Revísala antes de ejecutar.
  7. Ejecuta la consulta.
  8. Comprueba que se obtienen las mismas operaciones que aparecen en resultado.csv.
Resultado de referencia En los datos de práctica validados deben aparecer 5 operaciones.
Esta ejecución no viola la regla de una sola consulta del agente La restricción de una única llamada a execute_sql_readonly se aplica al agente. Esta es una verificación manual posterior realizada directamente por el alumno en BigQuery.

Si no aparecen 5 filas

Revisa, en este orden:

  1. que el JOIN sea por cuenta_id;
  2. que canal sea APP o WEB;
  3. que es_internacional = 1;
  4. que monto > 2000000 y no >=;
  5. que producto = 'Tarjeta de Crédito';
  6. que no existan filtros extra.
Paso 10

Generar una segunda consulta con Gemini en BigQuery

Objetivo

Construir una segunda consulta desde una instrucción autosuficiente y comparar su lógica y resultado con el SQL producido por el agente.

Prompt de verificación

Prompt de verificación · Gemini en BigQuery 
Genera una consulta GoogleSQL de solo lectura en BigQuery.

Utiliza exclusivamente estas dos tablas:
- `arched-osprey-506820-i9.analitica_bancaria_demo.movimientos_diarios`
- `arched-osprey-506820-i9.analitica_bancaria_demo.cuentas_productos`

Relaciona ambas tablas mediante `cuenta_id`.

La consulta debe seleccionar exclusivamente las operaciones que cumplan simultáneamente estas cuatro condiciones:
1. `canal` es APP o WEB.
2. `es_internacional` = 1.
3. `monto` > 2000000.
4. `producto` = 'Tarjeta de Crédito'.

Devuelve exactamente estas columnas, en este orden:
- movimiento_id
- cuenta_id
- fecha_movimiento
- hora
- tipo_movimiento
- canal
- monto
- moneda
- es_internacional
- categoria_contraparte
- cliente_id
- producto
- estado

No agregues filtros adicionales.
No agregues agregaciones.
No agregues GROUP BY.
No agregues ORDER BY salvo que sea estrictamente necesario para la lógica, lo que en este caso no debería serlo.

Devuelve solamente la consulta SQL.
  1. Genera la consulta.
  2. Revisa manualmente que la lógica sea correcta.
  3. Ejecuta el SQL generado.
  4. Comprueba que devuelve 5 operaciones.
  5. Compara esas operaciones con resultado.csv y con la consulta del agente.

Comparación final del paso 10

NivelQué debe coincidir
LógicaMismas dos tablas, JOIN por cuenta_id y mismas cuatro condiciones.
EsquemaLas mismas 13 columnas de salida.
ResultadoEl mismo conjunto de 5 operaciones.
El SQL no tiene que ser idéntico Gemini puede usar alias distintos o escribir INNER JOIN explícitamente. Lo importante es la equivalencia lógica y el mismo conjunto de registros.
Al terminar esta etapa Ya tienes la evidencia documental preparada, los tres entregables del agente y dos verificaciones directas en BigQuery. Solo queda revisar y cerrar la entrega.
